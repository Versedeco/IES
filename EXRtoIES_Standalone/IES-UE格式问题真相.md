# IES-UE导入错误真正原因和修复方案

## 🔍 问题诊断

### 错误信息
```
IES import failed: "V Values are not in increasing order"
```

### 真正原因

**不是角度顺序问题，而是角度格式问题！**

通过对比两个IES文件发现：
- ✅ **可导入的文件**（TD_5w_D5M.ies）：角度值**每行一个**
- ❌ **无法导入的文件**（TD_5w_D5M_New.ies）：角度值**在同一行，空格分隔**

## 🎯 为什么会有这个问题？

### IES标准的模糊性

IES-LM-63标准对角度值的格式要求有多种解释：
1. **宽松解释**：允许角度值在同一行，空格分隔
2. **严格解释**：要求每个角度值占一行

不同软件对标准的实现不同：
- **UE**：采用严格解释，要求每行一个值
- **其他软件**：可能接受同行多个值

### 错误信息的误导性

错误信息"V Values are not in increasing order"是误导的：
- ❌ 不是角度顺序问题（角度已经是递增的）
- ✅ 是格式问题（UE无法正确解析同行多个值）
- UE解析失败后，错误地报告为"顺序错误"

## 🔬 技术深入分析

### UE的IES解析逻辑

UE在解析IES文件时：

1. 读取数据行获取角度数量（如：37个水平角，73个垂直角）
2. **逐行读取**角度值
3. 如果一行有多个值，可能只读取第一个
4. 导致读取的角度数量不足
5. 剩余角度值被误解为光强数据
6. 最终报告"顺序错误"

### 为什么标准格式在UE中失败？

IES-LM-63-2002标准实际上允许灵活的格式：
- 允许数据在同一行（空格或换行分隔）
- 但UE的解析器实现较为严格
- 只接受传统的"每行一个值"格式
- 这是UE的历史遗留问题
